# Facility Operations 0.1.0

The first downloadable Facility Operations proof-of-concept release includes a compiled Splunk app installer. Install through Splunk Web without cloning the repository or building from the command line.

[Download the `.tar.gz` installer](https://github.com/LeiterConsulting/splunk-facility-operations/releases/download/v0.1.0/splunk_facility_operations-0.1.0.tar.gz) · [Installation guide](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.0/docs/getting-started.md#download-and-install-from-github) · [Presentation guide](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.0/docs/demo-guide.md)

## Install

1. Under release **Assets**, download `splunk_facility_operations-0.1.0.tar.gz`. Keep it compressed. The `.spl` asset is an identical alternative; `SHA256SUMS` contains both file hashes.
2. For an upgrade, back up local settings and populated live inventory using the [upgrade procedure](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.0/docs/getting-started.md#update-and-preserve-configuration).
3. As a Splunk administrator, open **Apps → Manage Apps → Install app from file**, choose the downloaded installer and **Upload**. Select **Upgrade app** only when intentionally updating an existing installation after backup.
4. Follow Splunk's prompts, open **Facility Operations**, select Demo and complete the [first checks](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.0/docs/getting-started.md#present-an-already-installed-app).

Choose the named installer rather than GitHub's automatic Source code archives. Git, Node.js, npm and additional pip packages are not required to install the compiled app. The release declares version **0.1.0**, build **6**, app ID `splunk_facility_operations`.

## Included

- Sixteen commercial and public sector verticals with audience-specific questions, dependency context, accountable owners and site conditions. Commercial walkthroughs include retail, manufacturing and technology.
- Audience, industry and use-case choices under **Settings → Presentation setup**, with remembered preferences and a clean dashboard.
- A repeating eight-phase synthetic incident with current timestamps, phase selection and presentation mode.
- A deterministic investigation assistant, bounded searches, chronology, evidence and draft exports. Ollama, OpenAI and Splunk AI Toolkit adapters are available for separately qualified connections.
- Change readiness, evidence review and governed action simulations. Unknown telemetry remains explicit in operational briefings.
- Compiled browser assets, Python handlers, Splunk configuration and demo observations. Release packages exclude local settings and always ship an empty live inventory.

## Verification and requirements

Release verification on October 7, 2026 passed **11 model/search/preferences tests, 16 Python tests and 4 browser workflows**, plus type checking, archive structure, checksum and package-content checks. The exact `.tar.gz` candidate was updated and exercised on standalone Splunk Enterprise **10.0.1 and 10.4.0**, including native searches, commercial investigation/export and Settings workflows.

AppInspect **4.3.1** precertification reported **0 errors, 0 failures and 0 future failures**, with four warnings and one skipped check. See the [dated validation and receipts](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.0/docs/validation.md#github-release-010-on-october-7-2026-build-6) for the package hash and scope.

Custom Mako templates must be enabled for the existing app entry shell. That shell is deprecated in Splunk 10.4 and requires migration for hardened deployments that disable it or future removal. Other warnings concern Python migration, custom configuration replication and Cloud role compatibility. This release does not establish Splunkbase certification, Cloud/GovCloud, cluster or future-version qualification.

Action execution is simulated. Reports are downloadable drafts; investigations are not durable incident records. The disconnected demonstration needs no external model or ingestion feed. Real model inference, customer sources, dependency authority, scale and production automation require their own evaluation.
