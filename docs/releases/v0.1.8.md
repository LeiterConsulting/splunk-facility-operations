# Facility Operations 0.1.8 — explain the incident, searches and response

The click-through now explains **what changed, why it matters, when it appeared, what was queried, how it can be addressed and how the authored incident response was applied**. Explanations are derived from returned stage observations and query receipts rather than a generic presenter caption.

## Experience

- A bounded root-component incident journal in the recurring synthetic dataset supplies baseline, detection, business impact, investigation, decision, intervention, verification and handoff records. Each use-case family provides its own mechanism to test, prechecks, concrete response detail, owner, reference and acceptance checks.
- Each guided stage retrieves both a latest snapshot and earlier observations through the selected phase. The walkthrough identifies the first returned diagnostic and business consequence, compares baseline/impact/current measurements and includes healthy counter-evidence. Later response records and later assistant/presenter context cannot explain an earlier stage.
- **What was queried?** shows completed snapshot, chronology and retained assistant searches, their purpose, actual available timestamps and returned row counts. Expand a query to inspect executed SPL. Local preview explicitly labels SPL as unexecuted.
- **When it happened** distinguishes authored T+ replay offsets, returned UTC observation times and query retrieval times. The looping dataset rebases UTC times when queried; click duration is not incident elapsed time or measured recovery improvement.
- Decision leads with the proposed response, accountable team, gate, prechecks and rollback. Recovery and verification lead with the queried authored intervention, concrete method, owner, application time and response reference. Presenter approvals/simulations/deferrals remain separate local records. Advancing the guide executes no infrastructure change.
- The scrolling explanation preserves visible Next/Back controls. Failed chronology searches clear the stage explanation and offer retry. The five-stage overview can retrieve earlier source records while retaining only its five visited screens.
- Story JSON retains each visited stage's narrative, chronology rows and query receipts. The customer Markdown brief retains the last captured explanation alongside current workflow facts and frozen assistant findings.
- Existing read-only assistant tools receive normalized incident/response fields. Deterministic reports and connected model instructions distinguish authored responses, actual presenter decisions and independent verification still needed. Activity shows actual UTC timestamps as well as elapsed time.

See the [presenter guide](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.8/docs/demo-guide.md#explain-the-what-why-when-and-response) and [architecture](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.8/docs/architecture.md#source-backed-incident-explanations).
