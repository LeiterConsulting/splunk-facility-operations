# Facility Operations 0.1.3

Facility Operations connects audience-specific operational briefings to investigations grounded in the selected data. Presenters can move from an abnormal dependency or evidence gap to its owner, affected functions, a focused assistant question and an exportable evidence packet, inside native Splunk chrome.

[Download the `.tar.gz` installer](https://github.com/LeiterConsulting/splunk-facility-operations/releases/download/v0.1.3/splunk_facility_operations-0.1.3.tar.gz) · [Install or upgrade](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.3/docs/getting-started.md#download-and-install-from-github) · [Guided investigation](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.3/docs/investigation-workflows.md)

## Changes

- **What matters now** connects observed business impact, waiting work, accountable teams, dependency hypotheses and missing evidence. Current healthy components outside a candidate footprint receive lower investigation priority without being declared cleared.
- **Investigate priority**, component/evidence handoffs and **Review with assistant** prepare a question in the current operational context. Focused investigations retain scope-wide consequences and inspect upstream/downstream relationships.
- Every provider receives the validated audience, selected component, dataset purpose, relevant fields, metric meanings and computed operational assessment. Live context uses observed business-function names and does not inject an authored root cause or demo action into the grounding packet.
- A **Retrieved evidence summary** separates computed facts from provider prose, freezes the investigation snapshot, and links back to current component evidence. JSON exports retain the assessment, data guide, scope, timestamps, results and executed SPL.
- Missing or invalid metrics stay unreported. Queue totals disclose reporting coverage, exclude unknown functions and can overlap across queues. Demo temperatures belong to the environmental component. Stale, missing or implausibly future current evidence stays unknown.
- Demo chronology covers only the current replay pass through the selected stage. Tool results disclose the 100-row boundary and unresolved inventory relationships. Audience-specific deterministic briefs and contextual prompts remain available without a model connection.
- Presenter, assistant, live-data and troubleshooting guides explain the workflow and evidence limits. Native Splunk chrome, Settings-based presentation selection, commercial/public-sector contexts, model discovery and simulated governance workflows remain available.

## Installation

App ID `splunk_facility_operations`; version **0.1.3**, build **9**. The `.tar.gz` and `.spl` assets are identical compiled installers. Upload the named installer through **Apps → Manage Apps → Install app from file**; keep it compressed. Installing the release requires no Node.js, npm or source build.

Back up local configuration and populated live inventory before upgrading, and follow your credential backup procedure. Select **Upgrade app** for an existing installation and follow Splunk's prompts. The package excludes local overrides and ships header-only live inventory; follow the linked guide to preserve configured inventory. Open the app, pause Demo at Impact, inspect the operational briefing and run **Investigate priority**.
