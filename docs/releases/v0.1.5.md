# Facility Operations 0.1.5 — industry workflows and business evidence

The demo now follows concrete business handoffs from source observation to operating consequence and the next decision. Clinical order acknowledgements, benefit requests, manufacturing quality release, warehouse/carrier handoffs, checkout, payments, property operations and other workflows have distinct measures and context.

## What changed

- Sixteen vertical reference designs define three named business handoffs each, comparable system roles, source families, correlation-field examples, owners, sites, dependencies, operating problems and recovery checks. Fourteen primary design references explain the concepts behind the authored scenarios.
- Situation room leads with completed/attempted counts, completion percentage, supplied objectives, p95, oldest waiting work and source signatures. A diagnostic comparison puts token response, gateway errors, database waits, circuit loss, UPS reserve and cooling alongside business consequences. The dependency map remains a drilldown.
- Source inspection shows the normalized observation, provenance, accountability, system equivalents and a synthetic deployment association where applicable. Evidence and controls includes an operational source ledger; facilities and change views connect their decisions to the industry workflow.
- The assistant receives the actual returned observations and independently computed delivery facts. Contextual prompts support business-handoff analysis and audience decisions; cited evidence and exports retain the operational fields. Provider instructions distinguish an acknowledgement from the final business outcome and reference products from installed integrations.
- Live sources can supply the optional bounded `operational` JSON contract. Missing measures and targets remain unreported; a newest observation with no measures cannot inherit an older aggregate.
- A build-specific persistent REST entry point and private import namespace load the correct runtime across app upgrades. Saved provider configuration is preserved.
- The [industry walkthroughs](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.5/docs/industry-scenarios.md) provide exact clinical, manufacturing and retail exercises, system equivalents, source provenance and customer evaluation questions. Installation, live onboarding, troubleshooting and contributor guidance cover the new contract.

## Install

App ID **splunk_facility_operations**, version **0.1.5**, build **13**. Download **splunk_facility_operations-0.1.5.tar.gz** from this release's assets and upload it, compressed, through **Apps → Manage Apps → Install app from file**. The `.spl` asset contains identical bytes. No source build or npm installation is needed. Follow the [installation guide](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.5/docs/getting-started.md#download-and-install-from-github).

Before upgrading, back up local configuration, credentials and populated live inventory; the shipped inventory is header-only. Select **Upgrade app**, follow Splunk's deployment/restart prompts and reopen the app. Provider settings were preserved on both verified labs.
