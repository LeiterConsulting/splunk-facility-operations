# Facility Operations 0.1.4

The investigation assistant now shows real search, model and tool activity while it works. Connected OpenAI and Ollama responses appear incrementally, and completed answers present readable evidence, dependency hypotheses, uncertainty and accountable next steps inside native Splunk chrome.

[Download the `.tar.gz` installer](https://github.com/LeiterConsulting/splunk-facility-operations/releases/download/v0.1.4/splunk_facility_operations-0.1.4.tar.gz) · [Install or upgrade](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.4/docs/getting-started.md#download-and-install-from-github) · [Connected investigation walkthrough](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.4/docs/investigation-workflows.md#show-a-connected-investigation)

## Changes

- **Investigation activity** displays actual searches, returned row counts, model calls, applied reasoning effort and tool execution. Executed SPL remains inspectable. The computed evidence receipt appears before the final answer.
- OpenAI Responses API streaming and Ollama NDJSON streaming publish public answer text as a draft. Function calls preserve provider state within the bounded investigation. AI Toolkit exposes search/tool activity and the completed response; token streaming through its `ai` command is not implemented.
- Answers render safe Markdown headings, emphasis, lists, code and tables. UTC timestamps replace raw epochs in model-facing evidence. Only citations to retrieved component IDs become interactive; model-authored HTML, images and external links are not executed.
- Cited components open frozen returned evidence in the conversation. An expandable abnormal event sequence supports chronology review. Follow-up controls prepare a counter-evidence question or audience-specific decision brief for review before submission.
- **Stop** requests server cancellation; leaving the assistant or changing scope prevents late answers from entering the conversation. Incomplete or failed responses cannot be exported as completed reports. Completed evidence exports include public activity and resource counts, with no provider reasoning.
- Authenticated, user-owned progress jobs use a private standard-library SQLite store on the search head and expire five minutes after creation. Limits bound concurrency, request rate, text and result size. Caller permissions continue to govern searches; provider credentials stay server-side.
- The Python service uses an app-specific runtime package and entry point. Demo guides, installation requirements, retention details, troubleshooting and connected-provider qualification instructions cover the new workflow.

## Installation

App ID `splunk_facility_operations`; version **0.1.4**, build **10**. The `.tar.gz` and `.spl` assets are byte-identical compiled installers. Upload the named installer through **Apps → Manage Apps → Install app from file**; keep it compressed. No Node.js, npm or source build is required on the Splunk server.

Back up local configuration, populated live inventory and credentials before an upgrade. Select **Upgrade app**, follow Splunk's deployment prompts and reload the app. Persistent Python handlers can retain older code until Splunk reloads/restarts the relevant service; see [troubleshooting](https://github.com/LeiterConsulting/splunk-facility-operations/blob/v0.1.4/docs/troubleshooting.md). The service needs writable `$SPLUNK_HOME/var/run/splunk` storage and Python's standard-library SQLite support. This release's updates preserved provider settings and other apps' reported versions/enabled states on both labs.
